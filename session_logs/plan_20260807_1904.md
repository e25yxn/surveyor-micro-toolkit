# แผนแก้บั๊ก #3: parse_pi_table — compound sub-row รั่วข้าม vertex boundary

**วันที่:** 2026-08-07
**สถานะ:** ร่างแผน รอ Claude Code implement ตาม Plan-Review-Approve (สเต็ป 1: แก้โค้ดตามแผนนี้เท่านั้น ยังไม่เพิ่มเทส/แก้ docs/commit)

## บั๊ก
`_flush_pending()` ใน `src/smt/builders/alignment_builder.py::parse_pi_table` คืนค่าทันทีเมื่อ `pending_pi is None` โดยไม่เคลียร์ `compound_arcs` — sub-row (POINT ว่าง + R มีค่า) ที่อยู่ก่อน PI ตัวแรก หรือหลัง EP จะรั่วไปเกาะ PI ถัดไปแบบเงียบๆ หรือหายไปเงียบๆ ท้ายไฟล์ (อ้างอิง session_logs/review_src_smt_20260802.md ข้อ #3)

เข้าเงื่อนไข Oracle correction exception ตาม CLAUDE.md:
- `.gs` มี defect เดียวกันยืนยันแล้ว (รัน `reference/gsheet/GS_PiTableParser.gs` จริงผ่าน Node ได้ผลตรงกัน — `flushPending_()` มี `if (pendingPi === null) return;` เหมือนกันบรรทัดต่อบรรทัด)
- VBA ไม่มีพอร์ตฟังก์ชันนี้เลย (เหมือนกรณี #2) → ไม่มี VBA divergence ต้องตาม

โค้ดปัจจุบัน (บรรทัด 261-296):
```python
def _flush_pending() -> None:
    nonlocal pending_pi
    if pending_pi is None:
        return
    if compound_arcs:
        ...
```

กรณีที่รั่ว:
1. **sub-row ก่อน PI ตัวแรก:** compound_arcs สะสมไว้ตั้งแต่ pending_pi ยัง None (ยังไม่เจอ PI ใดๆ) → เจอ PI แถวถัดไป เรียก `_flush_pending()` แต่ pending_pi ยัง None ตอนนั้น (เพราะ BP ไม่ set pending_pi) → return โดยไม่เคลียร์ compound_arcs → arc เดิมค้างไปรวมกับ arc ของ PI ที่เพิ่งถูกตั้งเป็น pending ตอน flush ครั้งถัดไป
2. **sub-row หลัง EP:** EP ไม่ set pending_pi → compound_arcs สะสมต่อไปจนจบไฟล์ → `_flush_pending()` เรียกครั้งสุดท้าย (บรรทัด 336) เจอ pending_pi is None อีก → return โดยไม่เคลียร์ → ข้อมูลหายเงียบๆ ไม่มี error ใดๆ

## ขอบเขต
เฉพาะ orphan sub-row ก่อน PI ตัวแรก / หลัง EP เท่านั้น **ไม่รวม** กรณี sub-row แทรกกลางหลัง PI ที่มี compound arc ถูกต้องอยู่แล้ว (นอกสโคป — เป็นความกำกวมของฟอร์แมตเอง แยกไม่ออกจากโค้ง compound หลายส่วนที่ตั้งใจจริง ไม่ใช่บั๊กนี้)

## จุดที่แก้ (2 จุด ในฟังก์ชันเดียว ไม่แตะส่วนอื่น)

1. เพิ่มตัวแปร `compound_arcs_first_line: int = 0` ในสโคปเดียวกับ `compound_arcs` (ใกล้บรรทัด 259)
2. ใน `_flush_pending()` บรรทัด 261-264: ก่อน `return` เดิมตอน `pending_pi is None` ให้เช็ค `if compound_arcs:` แล้ว raise ValueError อ้างเลขบรรทัดของ arc ตัวแรก ข้อความ:
   ```python
   f'compound sub-row (แถวที่ {compound_arcs_first_line}) มีค่า RADIUS '
   'แต่ไม่มี PI ก่อนหน้าให้ผูก '
   '(อยู่ก่อน PI ตัวแรก ก่อน BP, หรืออยู่หลัง EP) '
   'ตรวจสอบลำดับแถวในไฟล์ว่าไม่มีแถวตกหล่นหรือเรียงผิดที่'
   ```
3. ในลูปหลัก ก่อนบรรทัด `arc: dict[str, Any] = {'R': float(r_raw)}` (ประมาณบรรทัด 291): เพิ่มเช็ค ถ้า `compound_arcs` ยังว่างอยู่ (นี่คือ arc ตัวแรกของบล็อกนี้) ให้ `compound_arcs_first_line = line_no`

## ความเสี่ยง
- เปลี่ยนพฤติกรรมจาก "เงียบ/รั่ว" เป็น raise — ไฟล์ที่เคย parse ผ่าน (แต่ได้ผลลัพธ์ผิดแบบไม่รู้ตัว) จะ error แทน ถือเป็นพฤติกรรมที่ถูกต้องตามหลัก Oracle correction exception ไม่ใช่ regression
- ไม่กระทบไฟล์ที่ format ถูกต้องอยู่แล้ว — compound sub-row ที่ตามหลัง PI ที่ถูกต้องจะยังทำงานเหมือนเดิมทุกประการ เพราะ pending_pi ไม่ใช่ None ตอน flush ในกรณีนั้น (ยืนยันแล้วด้วย dry-run: pytest เต็มชุด 514 เดิมผ่านหมด + ทดสอบกับข้อมูลสนามจริง AL1 ไม่มี false-positive)

## ตัวอย่าง input จริง → output ที่คาดหวัง

**ตัวอย่าง 1 — sub-row ก่อน PI ตัวแรก (เดิมรั่ว):**
```
POINT,N,E,STA,R,LS,DELTA
,,,,150,,10
BP,0,0,0,,,
PI1,100,100,,300,,
```
- เดิม: compound_arcs=[{R:150,delta:10}] ค้างจาก orphan แล้วไปรวมกับ arc ของ PI1 แบบผิดๆ ไม่มี error
- ใหม่: raise ValueError ทันทีที่เจอ BP (แถวที่ 3): "compound sub-row (แถวที่ 2) มีค่า RADIUS แต่ไม่มี PI ก่อนหน้าให้ผูก ..."

**ตัวอย่าง 2 — sub-row หลัง EP (เดิมหายเงียบท้ายไฟล์):**
```
POINT,N,E,STA,R,LS,DELTA
BP,0,0,0,,,
PI1,100,100,,300,,
EP,200,200,,,,
,,,,150,,10
```
- เดิม: parse_pi_table คืน vertices 3 ตัว (BP,PI1,EP) เฉยๆ ไม่มี error ทั้งที่มีข้อมูล R=150 ที่ไม่ถูกใช้เลย
- ใหม่: raise ValueError ตอน `_flush_pending()` เรียกครั้งสุดท้าย: "compound sub-row (แถวที่ 5) มีค่า RADIUS แต่ไม่มี PI ก่อนหน้าให้ผูก ..."

**ตัวอย่าง 3 — control, format ถูกต้อง (ต้องไม่พัง):**
```
POINT,N,E,STA,R,LS,DELTA
BP,0,0,0,,,
PI1,100,100,,,,
,,,,300,,15
,,,,150,,
EP,200,200,,,,
```
- เดิมและใหม่: เหมือนกันทุกประการ — PI1 ได้ compound=[{R:300,delta:15},{R:150}] ไม่มี error เพราะ pending_pi=PI1 ไม่ใช่ None ตอน flush
