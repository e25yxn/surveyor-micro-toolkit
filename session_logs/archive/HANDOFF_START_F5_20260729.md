## 3. กฎเหล็กของโปรเจกต์ (ย่อ — เผื่อบริบทไม่ครบ)

- **Plan-Review-Approve เสมอ**: Claude Code เขียนแผน/draft → Claude Chat
  ตรวจก่อน → อนุมัติถึงเขียนไฟล์จริง
- **Commit message ผ่าน `.git/smt_commit_msg.txt` ด้วย heredoc ผ่าน Git Bash
  เท่านั้น** — **forward slash เสมอ ไม่ใช่ backslash** ตรวจ `cat -A` ก่อน
  commit ทุกครั้ง (ถ้าเจอ escape sequence แปลกๆ เช่น `M-BM-'`/`M-bM-^@M-^T`
  ให้ `xxd` ตรวจ byte จริงแทน มักจะเป็นแค่อักษร UTF-8 ปกติ ไม่ใช่ไฟล์เสีย)
- **ไฟล์ใหญ่/เขียนทับทั้งไฟล์/มีบรรทัดยาว**: ข้ามการโชว์ preview/diff ใน
  แชทไปเลย (พิสูจน์มาตลอดว่าไม่น่าเชื่อถือ) เขียนไฟล์จริงแล้ว**อัปโหลดไฟล์
  จริงจากดิสก์มาตรวจรอบเดียวจบ** แทน — ไฟล์เล็ก/บรรทัดสั้น (< 20 บรรทัด)
  โชว์ text ใน terminal ตรวจได้ตามปกติ
- **`session_logs/latest.md` append ผ่าน heredoc (`cat >>`) เท่านั้น** —
  ห้ามใช้ Update/Edit tool กับไฟล์นี้ (เคยทำ entry ไปแทรกผิดที่มาแล้ว)
  อนุญาตให้ auto-allow การเข้าถึงโฟลเดอร์นี้ได้ (ความเสี่ยงต่ำ)
- **`git push`/`clasp push` ต้องผ่าน Claude Chat ตรวจทุกครั้ง** ไม่ auto-allow
  แบบกว้างๆ — ต่างจาก read-only commands (`git status`/`diff`/`log`,
  `clasp status`) ที่อนุมัติเองได้เลย
- **`TestDrive.js` อยู่ที่ `D:\MyClasp_SMT_DEMO\TestDrive.js` เท่านั้น ไม่
  track ใน git** — อย่าพยายาม `git add` ไฟล์นี้
- **เลิกใช้ `BUNDLE_gsheet.md`/`BUNDLE_python_core.md` แล้ว** (2026-07-29) —
  แนบไฟล์จริงเฉพาะที่เกี่ยวข้องกับงานแทน
