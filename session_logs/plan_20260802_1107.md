# แผนแก้ F.6.3 — strip prefix "Error: " ก่อน match ERROR_MESSAGE_MAP (ทางเลือก A)

สถานะ: รอ Claude (แชท) ตรวจก่อน — ยังไม่ลงมือแก้โค้ด

## บริบท / เหตุผล

ยืนยันจากเคสจริงในเบราว์เซอร์แล้วว่า raw message ที่ client เห็นมี `"Error: "`
นำหน้าเสมอ (เช่น `Error: ไม่พบข้อมูล alignment ที่ครบถ้วนในตารางนี้...`) ซึ่งไม่มี
prefix นี้ตอนทดสอบผ่าน Node โดยตรง — เพราะ `throw new Error(...)` ทุกจุดใน
`.gs` (grep แล้วไม่มี try/catch เลยสักจุดในทั้งสาย GS_Pipeline.gs →
GS_TableSplitter → GS_PiTableParser → GS_AlignmentBuilder →
GS_Alignment/GS_CrossCheck) ใช้ `Error` object ธรรมดา ซึ่งตาม JS
`Error.prototype.name` มีค่าเป็น `"Error"` เสมอ — เข้าใจว่า prefix นี้มาจาก
runtime bridge ของ `google.script.run` เองตอน reconstruct exception ข้าม
server→client boundary (โค้ดฝั่งนี้ Google inject เข้ามา ไม่อยู่ใน repo)

CK1024 ยืนยันแล้วว่าหลักฐานพอ ไม่ต้องทดสอบแยกเคสเพิ่ม เพราะทั้ง 4 pattern ที่มี
`^` anchor ใน `ERROR_MESSAGE_MAP` (ดู session_logs/latest.md entry F.6.3)
มาจาก `throw new Error(...)` แบบเดียวกันหมด จะได้ prefix เดียวกันแน่นอน
ส่วนอีก 3 pattern ที่ไม่มี anchor เป็น substring search ไม่กระทบไม่ว่า prefix
จะเป็นอะไร

## ไฟล์ที่จะแก้

### 1. `reference/gsheet/Index.html` — แก้ `getFriendlyMessage()` (บรรทัด ~170-177)

**เดิม:**
```js
function getFriendlyMessage(rawMessage) {
  for (var i = 0; i < ERROR_MESSAGE_MAP.length; i++) {
    var m = ERROR_MESSAGE_MAP[i].test.exec(rawMessage);
    if (m) return ERROR_MESSAGE_MAP[i].friendly(m);
  }
  return 'เกิดข้อผิดพลาดที่ไม่ทราบสาเหตุแน่ชัด — กรุณาลองใหม่อีกครั้ง ' +
    'หากยังไม่หายกรุณาแจ้งผู้ดูแลระบบพร้อมข้อความรายละเอียดด้านล่าง';
}
```

**แก้เป็น:**
```js
function getFriendlyMessage(rawMessage) {
  // google.script.run เติม prefix ชื่อ error class (เช่น "Error: ") หน้า
  // rawMessage เสมอเมื่อ exception เดินทางข้าม server->client boundary จริง
  // (ไม่เกิดตอนเรียกฟังก์ชัน .gs ตรงๆ ผ่าน Node) — ตัดออกเฉพาะตอน match
  // pattern เท่านั้น ไม่กระทบ rawMessage ตัวเต็มที่โชว์ใน "รายละเอียดทางเทคนิค"
  var matchMessage = rawMessage.replace(/^[A-Za-z]+:\s*/, '');
  for (var i = 0; i < ERROR_MESSAGE_MAP.length; i++) {
    var m = ERROR_MESSAGE_MAP[i].test.exec(matchMessage);
    if (m) return ERROR_MESSAGE_MAP[i].friendly(m);
  }
  return 'เกิดข้อผิดพลาดที่ไม่ทราบสาเหตุแน่ชัด — กรุณาลองใหม่อีกครั้ง ' +
    'หากยังไม่หายกรุณาแจ้งผู้ดูแลระบบพร้อมข้อความรายละเอียดด้านล่าง';
}
```

`showError()` **ไม่แก้** — ยังคงเรียก `getFriendlyMessage(rawMessage)` ด้วย
`rawMessage` เต็ม และยังคงโชว์ `rawMessage` เต็ม (มี prefix ติดอยู่) ใน
`<details>` "รายละเอียดทางเทคนิค" เหมือนเดิม — ตัดเฉพาะสำเนาที่ใช้ match เท่านั้น

ทำไมใช้ `/^[A-Za-z]+:\s*/` แบบทั่วไป ไม่ hardcode เฉพาะคำว่า `"Error"`:
ครอบคลุม native GAS exception ชนิดอื่น (เช่น `Exception:`, `TypeError:`)
ที่ยังไม่เคยทดสอบจริงในเบราว์เซอร์ด้วย โดยไม่ต้องรอยืนยันทีละชนิด — ความเสี่ยง
คือถ้าในอนาคตมี custom error message ที่ตั้งใจขึ้นต้นด้วยคำอังกฤษ+colon จริงๆ
(ไม่ใช่ prefix แปลกปลอม) จะถูกตัดไปด้วย — ตอนนี้ตรวจแล้วว่าไม่มี pattern ไหนใน
7 pattern ปัจจุบันเข้าเงื่อนไขนี้ (ทุก pattern ภาษาไทยขึ้นต้นด้วยอักษรไทย
ยกเว้น pattern #3 `invalid numeric cell:` ซึ่ง colon อยู่หลัง 3 คำ ไม่ใช่ตำแหน่ง
แรกสุด — regex ไม่ match จุดนั้นเพราะไม่ใช่ anchor position)

### 2. ไฟล์ใหม่ `reference/gsheet/test_error_message_map.js` (commit ถาวร)

เหตุผลที่ต้องเป็นไฟล์ถาวร ไม่ใช่ scratch script แบบที่แก้ F.6.2 (สร้าง-รัน-ลบ):

เบราว์เซอร์มี — scratch script ที่ลบทิ้งหลังทดสอบป้องกัน regression แบบนี้

## ตาราง test case (input → output ที่คาดหวัง)

| # | rawMessage (input) | pattern ที่คาด | หมายเหตุ |
|---|---|---|---|
| 1 | `Error: ไม่พบข้อมูล alignment ที่ครบถ้วนในตารางนี้ — ต้องมีอย่างน้อยจุดเริ่ม (BP) และจุดจบ (EP) กรุณาตรวจสอบว่ากรอกข้อมูลครบหรือไม่` | index 1 (alignment ครบถ้วน) | เคสจริงที่เจอบั๊ก — ต้องได้ friendly message ไม่ใช่ catchall |
| 2 | `ไม่พบข้อมูล alignment ที่ครบถ้วนในตารางนี้ — ...` (ไม่มี prefix) | index 1 (เหมือน #1) | ยืนยัน backward-compat กับตอนเรียกตรงผ่าน Node/เดิม |
| 3 | `Error: ไม่พบ tab "Test_Sheet" ในไฟล์นี้` | index 0 (tab not found) | anchor `^...$` ทั้งคู่ ต้องรอดจาก prefix ด้วย |
| 4 | `Error: invalid numeric cell: "12,000"` | index 2 (invalid numeric cell) | ตรวจว่า strip แค่ครั้งเดียวตรงหน้าสุด ไม่ไปโดน colon ตัวที่ 2 กลางข้อความ |
| 5 | `Error: PI "PI7" (แถวที่ 12) มีรัศมีซ้ำกับ compound sub-row` | index 3 (PI compound) | anchor pattern ตัวสุดท้ายที่มี `^` |
| 6 | `Error: station 123.45 อยู่นอกแนวเส้นทาง` | index 4 (อยู่นอกแนวเส้นทาง) | pattern ไม่มี anchor — ต้องผ่านทั้งก่อน/หลังแก้เหมือนกัน (regression check) |

## ความเสี่ยง

1. Regex ทั่วไป `/^[A-Za-z]+:\s*/` อาจตัด prefix ที่ตั้งใจจริงในอนาคตถ้ามี
   custom error message ขึ้นต้นด้วยคำอังกฤษ+colon — ปัจจุบันตรวจแล้วไม่กระทบ
   7 pattern ที่มี แต่ต้องระวังตอนเพิ่ม pattern ใหม่ในอนาคต (จะเขียน comment
   เตือนไว้ในโค้ดจริงตอน implement)
2. สมมติฐาน root cause (`google.script.run` bridge เติม prefix) ยังไม่ได้
   ตรวจสอบเอกสารทางการของ Google ยืนยัน — อาศัยหลักฐานจากเคสจริงที่เจอ 1 เคส
   + เหตุผลทาง JS semantics (`Error.prototype.name` คงที่) ตามที่ CK1024
   สรุปว่าเพียงพอแล้ว ไม่ต้องทดสอบเพิ่ม
3. ไม่แตะ `.gs` ใดๆ เลยในแผนนี้ (แก้เฉพาะ client-side `Index.html` +
   เพิ่มไฟล์ test ใหม่) — ไม่มีความเสี่ยงต่อ pipeline คำนวณจริง
