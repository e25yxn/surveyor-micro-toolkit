## ส่วน A — ปรับ error handling ให้เข้าใจง่ายขึ้น

### A.1 โค้ดปัจจุบัน (อ่านแล้วจาก `reference/gsheet/Index.html`)

Error ทุกจุดในหน้านี้วิ่งผ่านฟังก์ชันเดียว:

```js
function showError(err) {
  var banner = document.getElementById('errorBanner');
  var message = (err && err.message) ? err.message : String(err);
  banner.textContent = 'เกิดข้อผิดพลาด: ' + message;
  banner.style.display = 'block';
}
```

เรียกจาก 4 จุด: `window.onload` (listCategoryFolders), `handleCategoryChange`
(listFilesInFolder), `handleFileChange` (listAlignmentTabsInFile), และ
`onCalcFail` (runFullPipeline) — ทุกจุดโชว์ raw `err.message` ตรงๆ

### A.2 error จริงที่เจอได้ในระบบนี้ (ไล่จาก source จริงใน `reference/gsheet/*.gs`)

| # | แหล่งที่มา (ไฟล์:บรรทัด) | ข้อความดิบปัจจุบัน | เกิดตอนไหน |
|---|---|---|---|
| 1 | `GS_Pipeline.gs:25` | `ไม่พบ tab "X" ในไฟล์นี้` | tab ถูกลบ/เปลี่ยนชื่อหลัง dropdown โหลดแล้ว (race condition) |
| 2 | `GS_PiTableParser.gs:86` | `invalid numeric cell: "abc"` (ภาษาอังกฤษล้วน) | เซลล์ตัวเลข (RADIUS/DISTANCE/ANGLE ฯลฯ) มีตัวอักษรหรือช่องว่างปน |
| 3 | `GS_PiTableParser.gs:108-111` | ข้อความยาวเทคนิคจัด พูดถึง "compound sub-row" | PI มีทั้งค่า RADIUS ที่แถวหลัก และมี compound sub-row ตามมา |
| 4 | `GS_Alignment.gs:311` (เรียกผ่าน cross-check) | `station X อยู่นอกแนวเส้นทาง` | จุดตรวจสอบไขว้ (cross-check) มี station นอกช่วง alignment |
| 5 | `GS_Alignment.gs:403` (เรียกผ่าน cross-check) | `จุดนี้ตกนอกทุก element (หรืออยู่ในช่วง spiral ของ Phase 1a)` | จุดตรวจสอบไขว้ตกนอกทุก element |
| 6 | `GS_CrossCheck.gs:257-261` | ข้อความยาวพูดถึง "vertexIndex", "scanRawRows_" | **บั๊กภายในระบบ** (invariant mismatch) ไม่ใช่ปัญหาข้อมูลผู้ใช้ |
| 7 | Google Apps Script เอง (`DriveApp.getFolderById` / `SpreadsheetApp.openById`) | เช่น `Exception: You do not have permission to access the requested document.` หรือ `Exception: Invalid argument: id` | ยังไม่ได้รับสิทธิ์เข้าไฟล์ / ไฟล์ถูกลบย้าย / id ผิด |
| 8 | (ไม่เข้าเคสไหนเลยข้างบน) | ข้อความอะไรก็ได้ | fallback ทั่วไป |

### A.3 ตัวอย่าง raw → friendly (อย่างน้อย 3 ตามที่ขอ ทำให้ครบทั้ง 8 เคสข้างต้น)

| # | Raw message (ปัจจุบันเห็นตรงๆ) | ข้อความใหม่ที่ผู้ใช้จะเห็น |
|---|---|---|
| 1 | `เกิดข้อผิดพลาด: ไม่พบ tab "Sheet3" ในไฟล์นี้` | **ไม่พบแท็บ (tab) ชื่อ "Sheet3" ในไฟล์นี้แล้ว** — อาจถูกลบหรือเปลี่ยนชื่อไประหว่างที่หน้านี้เปิดอยู่ กรุณาเลือกไฟล์ใหม่อีกครั้ง |
| 2 | `เกิดข้อผิดพลาด: invalid numeric cell: "12,5"` | **พบข้อมูลตัวเลขที่อ่านไม่ได้ในตาราง ("12,5")** — ตรวจสอบคอลัมน์ตัวเลข (เช่น RADIUS, DISTANCE, ANGLE) ว่ากรอกเป็นตัวเลขล้วนๆ ไม่มีตัวอักษร, comma, หรือช่องว่างปน แล้วลองคำนวณใหม่ |
| 3 | `เกิดข้อผิดพลาด: PI "PI-7" (แถวที่ 42) มีทั้งค่า RADIUS (300) และมี compound sub-row ตามมา...` | **ข้อมูลขัดแย้งกันที่ PI-7 (แถวที่ 42 ในตาราง)** — มีการกรอกค่ารัศมีไว้ทั้งที่แถวหลักและแถวย่อย (compound) ระบบไม่แน่ใจว่าจะใช้ค่าไหน กรุณาลบค่ารัศมีที่ซ้ำออกแถวใดแถวหนึ่งแล้วลองใหม่ |
| 4 | `เกิดข้อผิดพลาด: station 1234.5 อยู่นอกแนวเส้นทาง` | **จุดตรวจสอบบางจุดอยู่นอกช่วงแนวเส้นทาง (alignment)** — ตรวจสอบว่าค่า station ในตารางอยู่ในช่วง PC ถึง PT ของแนวนี้หรือไม่ |
| 5 | `เกิดข้อผิดพลาด: จุดนี้ตกนอกทุก element...` | ข้อความเดียวกับ #4 (จัดกลุ่ม pattern เดียวกัน — จุดตรวจสอบตกนอกแนวเส้นทาง) |
| 6 | `เกิดข้อผิดพลาด: GS_CrossCheck.checkPiCurves: scanRawRows_ นับแถว vertex ได้...` | **เกิดข้อผิดพลาดภายในระบบระหว่างตรวจสอบไขว้ (cross-check)** — ไม่ใช่ปัญหาจากข้อมูลของท่าน กรุณาแจ้งผู้ดูแลระบบพร้อมข้อความรายละเอียดด้านล่าง |
| 7 | `เกิดข้อผิดพลาด: Exception: You do not have permission to access the requested document.` | **ไม่มีสิทธิ์เข้าถึงไฟล์นี้** — กรุณาขอสิทธิ์เข้าถึง Google Sheet จากเจ้าของไฟล์ก่อน แล้วลองใหม่ |
| 8 | ข้อความอื่นที่ไม่เข้าเคสไหนเลย | **เกิดข้อผิดพลาดที่ไม่ทราบสาเหตุแน่ชัด** — กรุณาลองใหม่อีกครั้ง หากยังไม่หายกรุณาแจ้งผู้ดูแลระบบพร้อมข้อความรายละเอียดด้านล่าง |

ทุกกรณี raw message เดิมยังคงอยู่ (ไม่ทิ้ง) — ใส่ใน `<details>` แบบพับเก็บ
ป้ายกำกับ "รายละเอียดทางเทคนิค (สำหรับแจ้งผู้ดูแลระบบ)" ใต้ข้อความหลัก

### A.4 การออกแบบทางเทคนิค

เพิ่มฟังก์ชัน pure function ใหม่ใน `<script>` ของ `Index.html`:

```js
function getFriendlyMessage(rawMessage) {
  // อาเรย์ของ {test: RegExp, friendly: string} ไล่ตามลำดับ, เคสสุดท้ายเป็น catchall
  // คืนค่า string เดียว (friendly text)
}
```

ปรับ `showError(err)`:
- ดึง raw message เหมือนเดิม
- เรียก `getFriendlyMessage(rawMessage)` ได้ข้อความ friendly
- render เป็น 2 ส่วนใน banner: friendly text (แสดงตลอด) + `<details>` ที่มี raw
  message อยู่ข้างใน (พับเก็บ ค่าเริ่มต้นปิด)

ไม่แตะ `.gs` ใดๆ เลย (ข้อความ raw ยังคงเดิมทุกตัวอักษร ตามกฎ "ห้าม over-engineer /
ห้ามแก้ signature เกินจำเป็น") — งานนี้เป็นแค่ client-side text mapping

### A.5 ความเสี่ยง

| # | ความเสี่ยง | การจัดการ |
|---|---|---|
| 1 | Pattern matching (regex/substring) จับ raw message ผิด ถ้ามีคนแก้ข้อความใน `.gs` ภายหลังโดยไม่รู้ว่ามี mapping ผูกอยู่ | ยอมรับความเสี่ยงนี้เปล่าๆ (ไม่แตะ `.gs` ใดๆ เลยตามที่ตั้งใจไว้แต่แรกในข้อ A.4) — ถ้าเกิดขึ้นจริง ระบบ fallback ไปเคส #8 (catchall) โดยอัตโนมัติ ไม่ crash แค่ไม่ friendly เท่าที่ตั้งใจ |
| 2 | เคส #4/#5 (station นอกแนว) จริงๆ อาจไม่ถึงผู้ใช้ทั่วไปเลยถ้า cross-check ไม่ error ในทางปฏิบัติ (เป็น edge case) | ใส่ไว้เผื่อไว้ก่อน ไม่เสียหายถ้าไม่เคยเกิด |
| 3 | เคส #7 (ข้อความจาก Google Apps Script เอง) ข้อความจริงอาจต่างจากที่คาด (ภาษา/wording เปลี่ยนได้ตามเวอร์ชัน Google) | ใช้ substring แบบกว้าง (เช่นค้นหาคำว่า "permission" หรือ "Invalid argument") ไม่ match ทั้งประโยค |
| 4 | เพิ่มความซับซ้อนให้ไฟล์ที่เดิมไม่มี logic ฝั่ง client มาก | ฟังก์ชันเดียว ทดสอบแยกได้ด้วย Node (ดู A.6) ไม่กระทบส่วนอื่นของหน้า |

### A.6 วิธีทดสอบ

`Index.html` เป็น GAS/HTML service ไม่มี unit test framework อยู่แล้วในโปรเจกต์
(reference/gsheet ใช้ smoke test ผ่าน `node reference/gsheet/smoke_test.js`) —
แผนทดสอบ:
1. เขียน `getFriendlyMessage` เป็นฟังก์ชัน pure ล้วนๆ (ไม่แตะ DOM) เพื่อให้ extract
   มาทดสอบด้วย Node ได้ตรงๆ (คัดลอกทั้งฟังก์ชันมารันใน scratchpad script ชั่วคราว
   ป้อน raw message ทั้ง 8 เคสข้างต้น เทียบ output ตรงกับตาราง A.3)
2. รัน `node reference/gsheet/smoke_test.js` ยืนยันไม่กระทบของเดิม (23/23 ตามที่เคยผ่าน)
3. Manual smoke test ใน browser จริงหลัง `clasp push`: บังคับให้เกิด error จริง
   อย่างน้อย 2 เคส (เช่น เลือกไฟล์ที่ยังไม่ได้แชร์สิทธิ์ = เคส #7, กรอก tab name
   ที่ลบไปแล้ว = เคส #1) แล้วดู banner ในเว็บจริง

## ส่วน B — คู่มือ step-by-step (copy + deploy)

### B.1 ไฟล์ใหม่

`docs/DEPLOY_GUIDE.md` — ภาษาไทย เขียนสำหรับผู้ใช้ใหม่ (รุ่นน้อง) ที่ไม่เคยใช้
Apps Script มาก่อน

### B.2 โครงเนื้อหาคร่าวๆ

```
# คู่มือ Deploy SMT Web App สำหรับผู้ใช้ใหม่

## ก่อนเริ่ม
- ต้องมีบัญชี Google ของตัวเอง
- ต้องได้รับลิงก์ Apps Script project จาก CK1024 ก่อน (ทีละคน)

## ขั้นตอนที่ 1 — เปิดลิงก์และทำสำเนา (Make a copy)
1. เปิดลิงก์ที่ CK1024 ส่งให้ (เปิดใน Apps Script editor)
2. เมนู File > Make a copy
3. ตั้งชื่อไฟล์ตามที่ต้องการ (แนะนำใส่ชื่อตัวเองกันสับสน)
   → หลังจากนี้เป็นสำเนาของตัวเองเต็มๆ แก้/deploy อะไรไม่กระทบต้นฉบับของ CK1024

## ขั้นตอนที่ 2 — Deploy เป็น New deployment
1. เมนู Deploy > New deployment (**ห้ามใช้ "Test deployments"** — ใช้งานจริงไม่ได้ถาวร)
2. เลือกประเภท: Web app
3. Execute as: Me (ตัวเอง) — ตั้งอัตโนมัติเพราะเป็นสำเนาของตัวเอง ไม่ต้องแก้
4. Who has access: **ตั้งเป็น "Only myself" เป็นค่าเริ่มต้นเสมอ** — เพราะ
   Execute as = Me หมายความว่าใครก็ตามที่ได้ลิงก์เว็บแอปนี้จะรันโค้ดด้วยสิทธิ์
   ของเจ้าของ copy (ตัวเอง) ได้ทันที ถ้าเปิดกว้างกว่านี้โดยไม่จำเป็นเท่ากับ
   ให้คนแปลกหน้าเข้าถึงข้อมูล/สิทธิ์ของตัวเองผ่านเว็บแอปนี้ไปด้วย
   ถ้ามีความจำเป็นจริงๆ ต้องแชร์ URL ให้คนอื่นเปิดใช้งาน (ไม่ใช่แค่ตัวเอง)
   **ให้ถาม CK1024 ก่อนเปลี่ยนจากค่าเริ่มต้นนี้**
5. กด Deploy → คัดลอก Web app URL ที่ได้ (นี่คือลิงก์เว็บแอปของตัวเอง)

## ขั้นตอนที่ 3 — ขอสิทธิ์เข้าถึง Google Sheet ข้อมูล
1. แจ้ง CK1024 ว่าต้องการเข้าถึงโฟลเดอร์/ไฟล์ข้อมูลไหน
2. CK1024 แชร์สิทธิ์ผ่าน Google Drive ปกติ (แยกขั้นตอนจากการ copy ด้านบน)
3. ยืนยันว่าเปิดไฟล์ที่แชร์มาได้จริงก่อนใช้งานเว็บแอป

## ขั้นตอนที่ 4 — เปิดใช้งานเว็บแอปของตัวเอง
1. เปิด Web app URL จากขั้นตอนที่ 2
2. เลือกหมวด > ไฟล์ > alignment ตามลำดับ
3. กด "คำนวณ"

## หมายเหตุ
- โค้ดต้นฉบับอัปเดตเมื่อไหร่ ต้อง Make a copy ใหม่เอง (ไม่มี sync อัตโนมัติ)
- ถ้าเจอ error ดูข้อความบนหน้าจอก่อน ถ้าไม่เข้าใจ กด "รายละเอียดทางเทคนิค"
  แล้วส่งข้อความนั้นให้ CK1024
```

### B.3 ความเสี่ยง
